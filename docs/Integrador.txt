5. RESTRICCIONES TÉCNICAS ESTRICTAS
────────────────────────────────────────────────
  Backend:
    - Separar rutas por dominio usando APIRouter de FastAPI.
    - Usar inyección de dependencias con Depends(get_db).
    - Schemas Pydantic separados: XxxCreate · XxxResponse · XxxUpdate.
    - Habilitar CORS para que React pueda consumir la API.
    - Status codes HTTP correctos: 201 para POST, 404 para not found, etc.

  Frontend (React + TS):
    - type Moneda = 'ARS' | 'USD'  →  NUNCA usar strings libres para moneda.
    - Toda llamada HTTP centralizada en /src/services/api.ts.
    - Sin lógica de negocio en componentes: solo presentación + hooks.
    - Usar React Query o useEffect + Axios para fetching de datos.
    - Tailwind para estilos, Material Design 3 como referencia visual.
    - Nunca mezclar CSS inline con clases Tailwind.

  General:
    - No duplicar lógica entre frontend y backend.
    - No hardcodear URLs: usar variables de entorno (.env).
    - Separación estricta: /backend y /frontend como proyectos independientes.

────────────────────────────────────────────────
6. MÓDULOS Y ENDPOINTS ESPERADOS DEL BACKEND
────────────────────────────────────────────────
  /pacientes
    GET    /pacientes            → listar pacientes
    GET    /pacientes/{dni}      → obtener paciente por DNI
    POST   /pacientes            → crear paciente
    PUT    /pacientes/{dni}      → actualizar paciente
    GET    /pacientes/deudores   → listar pacientes con saldo > 0

  /turnos
    GET    /turnos               → listar turnos (filtro por fecha/doctor)
    POST   /turnos               → crear turno
    PUT    /turnos/{id}          → actualizar estado / cerrar con cobro
    DELETE /turnos/{id}          → cancelar turno

  /finanzas
    POST   /pagos                → registrar pago/cobro
    GET    /caja/hoy             → resumen del día (turnos + ingresos ARS/USD)

8. CÓMO PROPONER CAMBIOS (OpenSpec)
────────────────────────────────────────────────
  Al recibir un nuevo requerimiento:
    1. Crear carpeta: openspec/changes/<nombre-en-kebab-case>/
    2. Generar: proposal.md · design.md · tasks.md · specs/<modulo>/spec.md
    3. Registrar el cambio en docs/CHANGES.md con estado: PROPUESTO

  Convenciones de naming:
    Cambios:     kebab-case    (ej: refactor-backend-routers)
    Interfaces:  PascalCase    (ej: interface Turno)
    Campos:      snake_case    (ej: paciente_dni)
