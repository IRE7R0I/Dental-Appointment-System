## Dental Appointment System – Project Summary

### Overview
The **Dental‑Appointment‑System** is a web application that manages dental clinic operations:
- Patient management (create, edit, view, list)
- Appointment (turno) scheduling and history
- Payment tracking and account balance per patient
- Reporting of cash box, debtors, and financial summaries

The stack is split into a **backend API** and a **frontend SPA**.

---
### Backend (API)
- **Language**: Python 3.11
- **Framework**: **FastAPI** (RESTful API, automatic OpenAPI docs)
- **ORM**: **SQLAlchemy** with session management (`backend/database.py`).
- **Database**: Relational (SQLite in development, can be swapped for PostgreSQL/MySQL).
- **Routers** (`backend/routers/`):
  - `pacientes.py` – CRUD for patients, account retrieval, patient‑specific history (`/pacientes/historial`).
  - `turnos.py` – Turno (appointment) CRUD, patient‑turno linking.
  - `finanzas.py` – Payment endpoints (`/finanzas/pagos`), cash‑box summary.
  - `doctores.py` – Doctor catalog.
- **Schemas** (`backend/schemas/`) use **Pydantic** models for request validation and response serialization.
- **CORS** configured for the development front‑end URLs (`http://localhost:5173`).
- **Utility** functions (`backend/crud/`) encapsulate DB logic (create, read, updates, aggregates).

---
### Frontend (SPA)
- **Framework**: **React 18** with **TypeScript**.
- **Bundler / Dev Server**: **Vite** (fast HMR, `npm run dev`).
- **Styling**: **Tailwind CSS** (utility‑first classes, responsive design).
- **Routing**: **React Router v6** – main routes:
  - `/pacientes` – patient list (`PerfilPacientePage` handles list, profile view, edit via internal `vista` state).
  - `/pacientes/:dni/historial` – dedicated **HistorialPacientePage** showing a two‑column view (turnos on the left, full payment table on the right).
  - other pages: `/agenda`, `/pagos`, etc.
- **API Service Layer** (`frontend/src/services/api.ts`) abstracts HTTP calls (`fetch`) to the FastAPI backend.
- **State Management**: Local component state (`useState`, `useEffect`). The profile page uses a `vista` enum (`lista`, `perfil`, `editar`).
- **Icons**: Material Symbols via the `material-symbols-rounded` font.
- **Design components**: Reusable cards (`KPICard`, `Card`), gradient buttons for primary actions.

### How It Works (High‑level Flow)
1. **Client** loads the SPA (`npm run dev`).
2. **React Router** resolves the URL:
   - `/pacientes` → renders `PerfilPacientePage` in list mode.
   - `/pacientes?dni=XYZ` → same component reads query‑param, auto‑opens that patient’s profile.
   - `/pacientes/XYZ/historial` → loads `HistorialPacientePage` with patient data.
3. **API Calls** (via `services/api.ts`):
   - `GET /pacientes` – list all patients.
   - `GET /pacientes/historial?dni=XYZ` – patient‑specific clinical history.
   - `GET /finanzas/pagos?dni=XYZ` – all payments for a patient.
   - Additional CRUD endpoints for creating/updating patients, registering payments, etc.
4. **State Updates** trigger re‑render of UI components; Tailwind ensures responsive layout.
5. **Navigation Back Stack** is controlled by the query‑param approach, guaranteeing a predictable user journey.
